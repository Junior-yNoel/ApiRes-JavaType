## 2026-03-30 - Accessible Dynamic Search Filtering & Empty States
**Learning:** In lightweight client-rendered vanilla/TypeScript apps, real-time client-side search filtering silently replaces DOM nodes without triggering screen reader announcements unless the target container is marked as a live region (`aria-live="polite"` and `aria-atomic="true"`). Additionally, search inputs lacking explicit accessible labels cause assistive tools to rely solely on placeholders, which can disappear or fail accessibility guidelines. Pairing semantic labels (`.sr-only`), `type="search"`, `aria-controls`, and an explicit visual `.no-results` container provides both sighted and assistive tech users with unambiguous feedback during query changes.
**Action:** Always verify client-side filtered container elements have `aria-live="polite"` and pair search inputs with accessible `<label>` elements and polished empty state designs.
